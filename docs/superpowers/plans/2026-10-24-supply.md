# Supply Data (D7) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve, per network, the newest hourly supply snapshot (`GET /v2/network/supply`: total, burned, minted, escrowed, circulating, AMM, account reserves, each history-derived part with its coverage) and Xahau's minting per day by source (`GET /v2/network/supply/minted`).

**Architecture:** Migration 015 adds three Xahau ledger tables (`genesis_mints`, `imports`, `reward_claims`), written by two new pure parsers behind `MINT_PARSER_VERSION`, and the snapshot table `network_supply`. A new aggregator job, `supply`, the last of a tick, computes one snapshot at the ledger of D5's escrows sentinel in steps under a 5 s budget (account ranges of `account_states`, AMM fill-forwards, Xahau burned and minted) and writes one row an hour. The api reads the newest row, does the exact arithmetic, and asks D3's `FeatureCoverageService` for each part's coverage; the minted days are summed at request time from the three tables.

**Tech Stack:** TypeScript (strict), NestJS 10, ClickHouse 26.8 (`@clickhouse/client`), pnpm 10 workspace, jest + ts-jest, testcontainers, supertest, `bignumber.js`, native `bigint` for drops.

**Spec:** `docs/superpowers/specs/2026-10-24-supply-design.md` (cited "spec §n", "F<n>", "decision n"; the plan argues from the spec, executors read both). Program: `x-explorer/docs/superpowers/specs/2026-10-24-explorer-program-2-overview.md`.

**Branch:** `feat/explorer-data-2` in `DAPI = /Users/golobitch/github.com/GateHubNet/data-api-worktrees/explorer-data-2` (stacked on PR #20). D-env, D3, D4, D5 and D6 are built on this branch before Task 1. Commit here, never push.

## Review Focus

1. **Coverage incomplete, part by part, and on a testnet.** An escrowed figure missing old escrows makes circulating billions too high; the answer must say `complete: false` on `escrowed` and `circulating`, and on a testnet on every part. Tests: Task 9 `escrowed and circulating say complete false when the history starts after Escrow's enable ledger`, `an xrpl-testnet profile answers complete false on every part`.
2. **Rows written twice** (unmerged parts, a re-ingest) must count once: a ledger (Xahau burned), an account state (reserves), a mint, an import. Tests: Task 5 `counts a mint and an import written twice once`; Task 7 `counts a ledger and an account state written twice once`.
3. **A reward whose claim is not where the mint is**: the claim 5 ledgers before the slice, a failed claim, a mint with no `EmitDetails`. Tests: Task 5 `classifies a mint as a reward when its claim is 5 ledgers before the slice`, `a failed ClaimReward is still a reward's parent`, `a mint without EmitDetails is genesis_mint`.
4. **A cycle whose prerequisites are missing never writes a wrong row**: no sentinel or AMM behind (waits, warns once at the 10th tick), no reserve values (NULL, `reserves` left out), a pool created after L or deleted (holds nothing). Tests: Task 6 `waits without a sentinel`, `waits while amm_pools is behind L`, `leaves the reserve values NULL with neither network_state nor SetFee`; Task 7 `a pool created after L holds nothing at L`; Task 8 `warns once after 10 waiting ticks`; Task 9 `leaves reserves out without reserve values`.
5. **The minted days at their edges**: coverage starting mid-day skips that day (unless it is the network's first ledger), the running day is summed so far, a day with no mint is zeros, marker pages concatenate to the unpaged list both ways. Tests: Task 10 `skips the day the coverage starts in`, `keeps the first day when coverage starts at firstLedger`, `sums the running day so far`, `marker pages, both orders, concatenate to the unpaged list`.

## Rulings

1. **Recordings in `xahau/mint/`, not `xahau/recorded/`** (spec §10 Task 1). Re-running `record-fixtures` into `recorded/` rewrites its manifest's `found`, head and scan keys (only `cases`, `txs` and `ledgers` merge), and the existing Xahau snapshots read that directory. The invariant test reads both directories.
2. **`record-fixtures --below`** is added: Imports are rarer than one per 5,000 ledgers and `--want` stops at the first, so the second kind needs a scan that starts below the first find.
3. **`NetworkProfile.hasAmm` and `hasMinting`** are new. The spec says "a network that mints" and "where AMM exists" without a source, and D3's rule for a feature the network cannot have (the `mints` coverage on XRPL, decision 12) asks for a profile flag, as `hasDelegation` and `hasMpt` are.
4. **Where the job's tests live.** The step functions are shared, so their ClickHouse suite is `packages/shared/test/supply-job.e2e-spec.ts` (with the other shared jobs' suites); the wired job has `apps/syncer/test/aggregator-supply.e2e-spec.ts`. The spec put `supply-job.e2e-spec.ts` under the apps.
5. **Minted days in an index gap.** Every UTC day from the first covered day to the newest ledger's is a row; a whole day missing from the index reads zeros. The spec's "the index has a ledger in it" would need a read per day; gaps are an operational fault that coverage ignores too (D3 decision 17).
6. **`syncer_parser_anomalies_total{kind}` is new** (the spec allowed "the existing anomaly counter if one exists": none does), fed through `LedgerDiagnostics` like `ammUnclassified`, since parsers are pure.
7. **At least one step per run**, even past the tick's deadline (as `rates_daily` computes at least one day), so a cycle always moves; the budget then bounds the rest.
8. **The first account range starts at `r`** (not `r11`) so that nothing sorting before the first prefix escapes; the last ends at `s` as the spec says.
9. **Feature names** `fees`, `amm`, `account_states`, `mints` are this plan's; escrowed and circulating use D5's `escrows`.
10. **Coverage entries in D3's form** (consistency pass): each feature is a `COVERAGE_FEATURES` entry `{ parserVersion, startOf(profile) }` (D3 Ruling 4), not a `{ parserVersion, amendment? }` descriptor; `amm` and `mints` are `unavailable` where `hasAmm` / `hasMinting` is false, and `fees` and `account_states` start at `firstLedger`.
11. **ADR-0010 Amendment 9** (consistency pass): the amendments run in build order (D3 5 … D6 8), so D7's two items are Amendment 9 and D8's are 10.
12. **`pnpm lint` is not run** (consistency pass): the repository has no ESLint configuration (`docs/development.md` §4; D-env's Global Constraints), so `eslint --fix` fails; the checks before a commit and at the end are `pnpm format`, `pnpm build`, `pnpm test` and the `test:e2e` suites.
