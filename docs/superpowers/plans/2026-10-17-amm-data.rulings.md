# AMM data: rulings made during implementation

Every decision the controller made while executing `2026-10-17-amm-data.md` where the spec and plan were silent, ambiguous or in conflict, verbatim from the execution ledger: what was decided, why, and what it costs if wrong. The product decisions among them are also recorded in `docs/adr/0011-amm-data-and-swaps-as-exchanges.md`; R-A5 and R-A7 are process rulings about the build harness.

## Rulings

- Ruling R-A1: exchanges and account_exchanges get a skip index `INDEX amm_account_set amm_account TYPE set(1024) GRANULARITY 1` (Task 2), so `amm=only`/`/swaps` skip granules without AMM rows; "bounded" in Review Focus 5 means read_rows ≤ (granules holding AMM rows + 2) × index_granularity, asserted in Task 5 — the filter alone cannot bound a read on a non-key column — cost if wrong: a bigger read on pairs with interleaved AMM rows.
- Ruling R-A2: every new AMM ledger table gets `INDEX ledger_mm ledger_index TYPE minmax GRANULARITY 1` (Task 2); watermark scans ("changed since ledger") and day scans use it — cost if wrong: partition-wide scans each tick.
- Ruling R-A3: amm_daily and amm_volume read swaps per active pool through the pair key (`exchanges` WHERE pair = pool pair AND amm_account = pool AND ledger range), with the active pools of the window taken from amm_pool_states (R-A2 index); never a cross-pair scan of exchanges — cost if wrong: none (same results).
- Ruling R-A4: /v2/amm/pools sorts the (small, thousands of rows) amm_pools latest-version set in SQL by (value_native DESC, amm_account) with a keyset marker on both; it is exempt from the in-order EXPLAIN test and its read_rows bound is the table's row count — cost if wrong: revisit with an ordered aggregate if pools reach millions.
- Ruling R-A5: the FINDINGS content lives in packages/shared/test/fixtures/README.md section "XRPL AMM cases (xrpl/amm/)" (committed) instead of xrpl/amm/FINDINGS.md — the harness forbids subagents from writing report-like files; later tasks read that README section — cost if wrong: none (same content, different file).
- Ruling R-A6 (spec amendment §2.1): IOU/IOU pools appear in swap metadata ONLY as RippleState nodes carrying lsfAMMNode (0x01000000), with neither the pool AccountRoot nor the AMM node; pool detection = AccountRoot nodes with AMMID ∪ AMM nodes' Account ∪ for every RippleState with lsfAMMNode, the side that owns the reserve (lsfLowReserve → LowLimit.issuer, lsfHighReserve → HighLimit.issuer); an LP-token trust line alone (lp_token_transfer) does not make a pool "touched" (no state row, no swap). Task 3 implements it and updates spec §2.1 and the "How AMM activity looks" facts accordingly — cost if wrong: missed IOU/IOU swaps (covered by the unclassified counter).
- Ruling R-A7: the harness blocks subagents from writing report files — implementers and reviewers return their full report as the final message (≤ ~120 lines) and the controller saves it to task-N-report.md; dispatch-rules.md updated — cost if wrong: more controller context per task.
- Ruling R-A8: accept Task 2 calls — `_f` shadows on state/liquidity amounts (aggregates keep exact String sums, only value_native Float64); amm_daily PARTITION BY toYYYYMM(day); amm_pools.created_ledger/created_by Nullable (pools first seen mid-life); no pair columns on liquidity/governance tables (resolved via amm_pools/amm_pool_states) — cost if wrong: one column add each.
- Ruling R-A9: accept Task 3 calls — ParsedAmmSwap gains optional autobridged_currency/_issuer; `unclassified` counts every touched pool that yields no swap/liquidity/governance row plus unknown-pair pools and unresolvable lsfAMMNode lines; a deleted pool's state keeps fee/auction fields from FinalFields with lp_supply '0'; XRP amounts in whole XRP (ExchangeParser convention), IOU/LP via BigNumber.toString(); mode only when exactly one mode flag — cost if wrong: counter noise, one-line field mappings.
- Ruling R-A10: AMM swap amounts stay the POOL's deltas (spec §2.3), which on the asset the pool pays out include the issuer's transfer fee (83.28354 paid vs 83.11731 received), whereas book rows use the offer's TakerGets change (fee excluded); the pure parser cannot know the issuer's TransferRate. Documented in ADR-0011 and api-reference (Task 11); fee estimates (Task 7) use the pool's input side only — cost if wrong: rates of pools with fee-charging issuers biased by ≤ the transfer fee.
- Ruling R-A11: accept Task 4 calls — ledgers.exchanges_count (and so /v2/stats exchanges counts) includes AMM swaps, following the user's decision that AMM swaps are exchanges everywhere; the recorded-xrpl exchanges e2e count rises 20 → 54 (book + AMM) for the same reason; range-ingest exposes the counter via its log line (the CLI has no scrape endpoint); RangeIngestResult unchanged — cost if wrong: stats exchange counts include AMM (a filter later).
- Ruling R-A12: accept Task 5 calls — /v2/exchanges?amm=only reads the remaining range in one skip-index-narrowed read instead of R107 windows (a page costs ≈ all swap granules of the range; a ledger-ordered swaps index is the follow-up if swaps reach millions); /v2/active_accounts include_exchanges objects also carry amm_account as last key (they are exchange objects) — cost if wrong: one-line revert / follow-up index.
- Ruling R-A13 (pre-dispatch T7): amm_daily follows the roadmap's cadence rule — runs every 5 ticks (today + yesterday, then newest-first back-fill under AGGREGATOR_AMM_DAILY_BUDGET_MS = 4000), R86 finality via a per-day sentinel, R87 failed-last, dirty-slice hook — the AMM plan predates the cadence rule — cost if wrong: daily AMM stats lag up to 5 minutes.
- Ruling R-A14 (load-bearing, from T6 concern 3): ledger_mm granule pruning is ineffective once amm_pool_states parts merge (sorted by pool); add a narrow ledger table `amm_pool_touches` (ledger_index, tx_index, amm_account), P6, ORDER BY (ledger_index, tx_index, amm_account), one row per amm_pool_states row, written by buildLedgerRows/LedgerWriter (CHILD_TABLES + LEDGER_KEYED_TABLES); poolsChangedSince, ammPoolsWatermark's stale-pool scan (where possible) and poolsClosedIn read it by primary-key range; Task 7 uses it to find a day's active pools — cost if wrong: one more small ledger table.
- Ruling R-A15 (from T6 concern 4): a failing amm_pools batch is bisected to isolate failing pools; isolated failures go to an in-memory retry set with backoff (5 min doubling to 1 h, keyed by pool) and the cursor advances past them; failures counted; a restart recomputes the watermark from stale pools, which naturally includes them — cost if wrong: a failing pool's state stays stale until its retry.
- Ruling R-A16: spec §3 pool value for an asset without a native leg is 2 × reserve ÷ (units-per-native rate); created_ledger/created_by come from amm_liquidity create rows (earliest) — amend spec §3 — cost if wrong: none (code already does this).
- Ruling R-A17 (pre-dispatch T7): amm_daily per-day sentinel = row with amm_account '' carrying the set version; finality in a new column final UInt8 (sentinel only); config_version = AMM_DAILY_CONFIG_VERSION 1 — the T2 schema has no finality column and volume's rate_f trick has no analog — cost if wrong: one column.
- Ruling R-A18 (pre-dispatch T8): amm_volume components read active pools from amm_pool_touches (PK range), their pairs from amm_pool_states (PK prefix, not amm_pools), then ONE exchanges read by pair-tuple IN + amm_account IN + ledger range (pairSums' SQL, dedupe and dust rule) — R-A3 forbids cross-pair scans — cost if wrong: a live 30day read covers all trades of AMM pairs in the window each tick (same order as trade volume).
- Ruling R-A19 (pre-dispatch T8): amm_volume conversion = trade components' rules, with the native-rate map taken from configured native markets first, then AMM pools against native in the same window; shared conversion code — spec says "converted like trade components" but unconfigured pool assets would otherwise all be dropped — cost if wrong: different native rates for tokens that only trade on AMM.
- Ruling R-A20 (T7 concerns 1–4): accept — slot discount only while the slot is unexpired (rippled's rule; stale slots in real data would overstate discounts); unknown fee → fee 0 with volume counted; no dust filter in per-pool stats; create = deposit, clawback = withdrawal; computeAmmDaily returns rows written; ammDaysDone(days: Date[]) — cost if wrong: a small estimate difference on edge swaps.
- Ruling R-A21 (T7 I1): bound the fill-forward with an exact windowed read — a shared helper in amm-pools.job.ts reads state rows `ledger_index BETWEEN from AND upTo` and falls back to a full-history read only for the pools whose needed fields are still null in the window; amm_daily uses from = day's first ledger − AMM_FILL_WINDOW_LEDGERS (≈ 7 days of ledgers); results identical to the full read (oracle tests unchanged). Yesterday is not recomputed once its newest set is final with the current config_version (the dirty path covers rewrites); a back-fill early return goes through mayStartSet (warn + budgetHit); at least one closed day starts per run when the back-fill has wanted days — cost if wrong: a slow day may overrun the tick once per 5 ticks.
- Ruling R-A22 (T7 I2): an amm_daily_dirty failure is counted, its day goes to an in-memory retry set with the closed-day back-off (5 min doubling to 1 h) drained by the amm_daily job, and the slice completes — cost if wrong: a failing dirty day stays stale until its retry succeeds (lost on restart; restart recomputes recent days and ammDaysDone covers finality).
- Ruling (T7 spec extra): the implementer's spec §1/§4 edits are accepted as controller-owned text (they match R-A17/R-A20).
- Ruling R-A23: fix in round 2 — fillForward's fallback walks back in doubling spans (exact, last pass = full read, jump to 0 once span ≥ upTo/2) + read_rows test; the floor may take a due owed day when no closed day is wanted first (owed days otherwise starve while today > 4 s); amm_daily requires carry_* columns only for pools with swaps; fix the two cost doc comments — cost if wrong: a few extra round trips per recompute.
- Ruling R-A24 (pre-dispatch T9): AMM objects use flat Ripple-style keys (base_currency/base_issuer/…), amounts and value_native as strings (precision8 for value), trading_fee as stored integer, auction fields grouped as auction_slot{holder, price, discounted_fee, expiration}, deleted boolean, key order written once in amm-objects.ts and pinned — spec leaves the shape open — cost if wrong: object shape churn before release.
- Ruling (T8 minors): fix minors 1, 2, 3, 6 now in one small round (cheap, task-local, cost on every tick) rather than load the single final-review fix wave: AMM live sets read only the native markets whose base is an asset of a non-native pool (skip when every pool is native); touches read returns min(ledger_index) per pool and pairs are read by (amm_account, ledger_index) IN zip (≈ one granule per pool); VolumeComponent doc notes the 0/0 exception and a market rate of 0 no longer blocks the pool-derived rate (?.gt(0)); duplicated alias doc and >120-char comment lines — cost if wrong: one more short round.
- Ruling (T9 concern 1): value_native must be fixed-point — 8 significant digits without exponent form (`new BigNumber(x.toPrecision(8)).toFixed()`) — send with the review fixes — cost if wrong: none (format only).
- Ruling (T9 concerns 3–7): accept — detail/pair 404 until the pool's first amm_pools tick (≤ 60 s) is documented, history from states; sentinel read per window day is fine — cost if wrong: a brief 404 for a brand-new pool.
- Ruling (T9 minor 2): accept asset filter before the newest-version pick — a pool account's pair never changes, the either-side match is order-independent, and moving it outside sorts all of amm_pools — cost if wrong: none while pairs are immutable (they are derived into the account).
- Ruling (T10 concerns 1–7): accept — /swaps keeps the exchange route's limit 200/400 (spec: "the same params as /v2/exchanges/:base/:counter" is the more specific rule over the global 1000); positions unpaged per spec; no currency index on balance_changes (bounded by the account prefix); event objects without pair — cost if wrong: a limit change / an extra index later.
- Ruling (T10 ⚠️): /swaps ignores `amm` (the route is always amm=only for one pool; a filter value cannot change it) — documented in Task 11 — cost if wrong: amm=bogus answers 200 instead of 400 on /swaps.
- Ruling (T10 minors): fix 1–8 now in one short round (task-local; keeps the final fix wave small): exact quotients unrounded (30 digits only when non-terminating) with an independent oracle, delete the swallowed assertion, move copied e2e helpers to test/support/amm.ts, Swagger enums from AMM_LIQUIDITY_EVENTS/GOVERNANCE_TYPES, ledgerDates reused by the history route, exported PagingQuery, one assetOf, drop onlyPoolsWithOlderRows for positions, ammAccount on a swaps-only query type, dateOf into common/params, positions math into its own file — cost if wrong: one more short round.
- Ruling R-A25 (final, I1): bound amm_daily without changing results — warn when one day's compute passes the job budget; floor each pool's walk at its own first state ledger (one grouped min(ledger_index) read per chunk; drop a pool from the walk once a step reaches it; the last jump goes to the lowest first ledger left, not 0) — exact, also speeds amm_pools; one walk with a per-pool required list (closing + carry for swap pools). Incremental "today" stays a follow-up unless the round-trip count is still high — cost if wrong: a slow mainnet day still overruns, now visibly.
- Ruling R-A26 (final, I2, amends R-A20): fees_base_est / fees_counter_est become Nullable(String); a side is null when any swap with its input on that side had no known fee; PoolDay omits the key when null (CSV empty cell) — the "unknown → 0" reading of R-A20 made zero indistinguishable from unknown for most pools — cost if wrong: one nullable column pair.
- Ruling R-A27 (final, Minor 1, amends R-A22): a failed amm_daily_dirty day is marked durably by copying the current set under a new version with final = 0 (INSERT…SELECT), so readers keep the same rows and the back-fill redoes the day after a restart; the in-memory owed retry stays as the fast path — cost if wrong: one extra set version per failure.
- Ruling R-A28 (final, Minor 2): an agg_dirty slice also rebuilds the pools whose newest amm_pools.last_ledger falls in the slice; a pool with no state rows left is removed with a lightweight DELETE from amm_pools — cost if wrong: a phantom pool after a parser fix.
- Ruling (final, parked 14/15): ESLint tooling and the balance_changes LP skip index are separate follow-up PRs; window amm=only from touches and persisting the amm_pools cursor are follow-ups.
- Ruling (residuals, all follow-ups — none load-bearing): (1) the grouped min(ledger_index) read costs the API history carry-in ≈ the pool's narrow history per request for a pool whose AMM-node row is beyond the 2048-ledger window — follow-up: per-pool `ORDER BY ledger_index LIMIT 1` looks; (2) the R-A28 DELETE has no `head === 0` guard — reachable only by a set-aside retry inside a --reprocess chunk window, transient (the chunk's slice rebuilds the pool) — follow-up: skip the delete when head is 0 and fix the :604 comment; (3) markAmmDayOwed has no abort signal — idempotent, harmless; (4) a pool set aside in a dirty slice is not stale by IS_STALE after a restart (heals on its next touch) — follow-up, cost if wrong: one pool's amm_pools row stale until it trades; (5) R-A28 does not rebuild a pool whose dropped row was below a surviving newer row — within the ruling; (6) per-request listeners remain in apps/api unit specs pagination.spec.ts:304, 350 and csv.interceptor.spec.ts:109 — follow-up.

## Deferred items and follow-ups

Findings that reviews judged non-blocking and the controller deferred (some were later fixed in the final fix wave — the final-wave rulings above say which). Open follow-ups after the final review:

- ESLint tooling: no eslint dependency or flat config exists and every `lint` script runs `--fix`; a separate tooling PR should add a flat config with typescript-eslint and make `lint` check-only.
- An LP skip index on `balance_changes` (`INDEX lp_mm startsWith(currency, '03') TYPE minmax GRANULARITY 1`) so `amm_positions` stops scanning the account's whole balance history.
- Window `/v2/exchanges?amm=only` from `amm_pool_touches` instead of one read over every swap granule of the range.
- Persist the `amm_pools` cursor if the start-up stale scan of `amm_pool_touches` proves slow at mainnet scale.
- An incremental "today" for `amm_daily` (recompute only pools touched since the last set and copy the rest forward) if a full mainnet day still overruns its budget; the per-asset `dailyNativeRates` round trips now dominate its cost with IOU/IOU pools.
- Per-pool `ORDER BY ledger_index LIMIT 1` first-ledger looks instead of the grouped `min(ledger_index)` read (cheaper for the API history carry-in of busy pools).
- A `head === 0` guard on the R-A28 `amm_pools` DELETE (and the stale comment near it).
- A pool set aside in a dirty slice is not stale by `IS_STALE` after a restart; it heals only on its next touch.
- Per-request supertest listeners left in `apps/api/src/common/pagination.spec.ts` and `csv.interceptor.spec.ts` (the e2e harness now uses one 127.0.0.1 listener).
- A rate option for `range-ingest` (public nodes throttle at 2 requests in flight).
