# Ripple drop-in: rulings made during implementation

Every decision the controller made while executing `2026-10-15-ripple-dropin.md` where the spec and plan were silent, ambiguous or in conflict, verbatim from the execution ledger: what was decided, why, and what it costs if wrong. Deliberate deviations from data.ripple.com are summarised in `docs/adr/0010-ripple-v2-wire-compatibility.md`.

- Ruling: work on branch feat/ripple-dropin in the main checkout instead of a separate git worktree — node_modules (incl. private @gatehub/toolbox) is installed here and the repo was only just initialised; cost if wrong: less isolation from edits the user makes in the same folder during the run.
- Ruling R1: T2 implementer records whether partition-scoped lightweight DELETE works in its report; T11 implements whichever form the T2 report says works — the file named in T2 does not exist yet — cost if wrong: T11 picks the slower ALTER…DELETE form.
- Ruling R2: T12 builds AppModule with a worker→module registry that starts EMPTY (plus liveliness/prometheus/ClickHouse/NodeClient); T13/T32/T33/T34 each add their module to the registry — modules can't be imported before they exist — cost if wrong: small registry refactor.
- Ruling R3: if a live endpoint is unreachable in T4, record what is reachable, mark the rest BLOCKED in the report, and make Xahau-fixture-dependent tests in later tasks `describe.skip` with an explicit reason only when the fixture dir is empty — cost if wrong: Xahau parser coverage deferred to T38 smoke.
- Ruling R4: T8 invariant (c) is replaced by a meaningful conservation check — per tx and IOU (currency, issuer-pair) Σ amount_change over all rows = 0; per tx native Σ amount_change over all rows (incl. fee row) = −Fee (drops→native) on XRPL; on Xahau skip native conservation for ClaimReward/GenesisMint/Import/emitted txs — the plan's version is true by construction — cost if wrong: a test needs loosening for an exotic tx type.
- Ruling R5: T13 builds its synthetic contiguous chain from a ripple-mock ledger (always present) instead of a recorded one — removes a network dependency — cost if wrong: none material.
- Ruling R6: Xahau definitions fallback lives at packages/shared/config/definitions/<network>.json (config/ ships via package `files` and resolves from src and dist identically); remove the src/dist candidate list; Task 4 copies server_definitions there (not src/network/definitions) — the plan's src path does not survive `pnpm deploy` packaging — cost if wrong: one path to move again.
- Ruling R7: ClickHouseService.insert must set `async_insert: 0` per insert (26.8 defaults async_insert=1, whose dedup is off by default and which weakens the child-rows-then-commit ordering) — LedgerWriter's exactly-once design depends on sync inserts with dedup tokens — cost if wrong: slightly lower insert throughput (negligible at our batch sizes).
- Ruling R8: non_replicated_deduplication_window applies to the 14 ledger-derived tables (the ones LedgerWriter inserts with tokens), not fee_stats/validations/aggregates/internal — "base and secondary" in the plan means the ledger-keyed tables — cost if wrong: none (other tables never use tokens).
- Ruling R9: a wanted type counts as "found" only on a tesSUCCESS tx — failed txs don't exercise parsers — cost if wrong: none.
- Ruling R10: keep source_tag/destination_tag = 0 (use !== undefined), deviating from Ripple's truthiness check — dropping tag 0 loses a real routing tag (outright bug under the Fidelity rule; GateHub depends on dest tags) — cost if wrong: Ripple clients see `destination_tag: 0` where they saw no key.
- Ruling R11: parser delivered_amount falls back to Amount when deliveredAmount() is 'unavailable' (matches payment.js); TxObject meta.delivered_amount still shows 'unavailable' — fidelity — cost if wrong: pre-2014 partial payments over-report delivered amount (as Ripple did).
- Ruling R12: exchanges with an underivable rate (zero leg) or MPT amounts are skipped instead of stored as NaN/Infinity like the reference — outright bug fix — cost if wrong: such rows missing (none in fixtures).
- Ruling R13: inverted rate keeps Ripple's quality.pow(-1) with BigNumber 20 decimal places (precision loss only for rates < ~1e-12, i.e. spam tokens) — parity with served rates — cost if wrong: <8 sig digits on dust-token rates.
- Ruling R4b (amends R4): Task 8 native conservation invariant (Σ native amount_change incl. fee row = −Fee) exempts Escrow*/PaymentChannel* (native moves into non-AccountRoot objects) and on Xahau ClaimReward/GenesisMint/Import plus any tx with EmitDetails/hook executions; IOU conservation stays strict — R4 as written would fail on legitimate data — cost if wrong: exempted types lose a conservation check.
- Ruling R14: no fee row when Fee is 0 (Batch inner txs) and AMM pseudo-account balances are kept as ordinary balance changes — a 0 fee row is noise; AMM pools are real AccountRoots — cost if wrong: Ripple-style clients see no transaction_cost row for Batch inners.
- Ruling R15: a request timeout recycles the shared connection (other in-flight requests fail over) — a timed-out socket is the common stuck-socket symptom and LiveRunner/RangeRunner retry per ledger anyway — cost if wrong: extra reconnect churn when one huge ledger is merely slow (mitigated by GH_LEDGER_FETCH_TIMEOUT_MS=120000).
- Ruling R16: every LedgerWriter insert carries query_id `${runId}:${table}:${first}-${last}:${chunkNo}`; add `awaitQuiescence(ch, runId, {timeoutMs})` (poll system.processes until no query_id LIKE '<runId>:%'; then KILL QUERY … SYNC for stragglers past timeout); LiveRunner/RangeRunner call it for the failed runId BEFORE any tail cleanup — a client-side timeout can leave an INSERT running server-side that lands after the DELETE, creating orphans/duplicates — cost if wrong: a few seconds' extra wait on recovery.
- Ruling R17: root pnpm override reflect-metadata→0.2.2 accepted (dedupes @nestjs/common/core copies pulled by toolbox; terminus failed to boot otherwise; API needs it too) — cost if wrong: a pinned transitive dep to revisit on toolbox upgrade.
- Ruling R18: apps import toolbox via `@gatehub/toolbox/lib/<module>` subpaths, never the package root (root import loads database/queue config and exits without GH_DATABASE_*) — carry to Task 15 — cost if wrong: deep imports break on a toolbox layout change.
- Ruling R19: toolbox bootstrap() never enables shutdown hooks → each app gets a small `ShutdownSignals` provider (SIGTERM/SIGINT → run registered async cleanups with a 10 s cap → process.exit(0)); Task 13 registers LiveRunner stop + lease release + NodeClient stop; Task 15 the API equivalents — clean lease release avoids a 30 s boot stall on redeploy — cost if wrong: crash-safe design still recovers; only slower restarts.
- Ruling R20: worker list env var is GH_WORKERS (toolbox @ConfigValue naming) instead of spec's GH_SYNCER_WORKERS — docs updated in Task 37 — cost if wrong: one rename.
- Ruling R21: lease release = insert a NEWER heartbeat row with empty holder (not heartbeat 0) — ReplacingMergeTree(heartbeat)+argMax keeps the newest row, a heartbeat-0 row would be ignored — cost if wrong: none.
- Ruling R22: empty-DB boot records the chosen start ledger as a live intent in ingest_log (run_id 'live:<bootId>', range_start=range_end=start, status 'started', marked 'done' after first commit); on a later empty-DB boot delete orphans above (min(start, earliest unfinished live-intent start) − 1) — head moves between boots, so start−1 misses a crashed first write's orphans; deleting above 0 could hit a concurrent range ingest — cost if wrong: small extra table reads at boot.
- Ruling R23: lease is self-fencing — every heartbeat first reads the current holder; if it is another holder, the runner halts (state 'halted', stop writing, liveliness 503) — prevents two writers after a stall-takeover — cost if wrong: an unnecessary halt if clocks skew badly (heartbeat age uses server now64()).
- Ruling R24 (raised from reviewer Minor 2): LiveRunner never commits a batch spanning a `ledgers` partition (flush before the next million) — partial multi-partition commit could place the checkpoint above a gap → silently skipped ledgers — cost if wrong: one extra small flush per million ledgers.
