# NFTs and URITokens: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ingest, store and serve XRPL NFTokens and Xahau URITokens: activity and sales, ownership and collections, sales volume and daily collection stats.

**Architecture:**
- A pure `nft.parser.ts` derives NFT events. On XRPL it uses `NFTokenPage` and `NFTokenOffer` diffs; on Xahau it uses `URIToken` diffs.
- The events go into four ledger tables.
- The aggregator rebuilds `nfts`, `account_nfts`, `nft_collections` and `nft_daily`, and adds an `nft_volume` metric.
- New `/v2/nfts`, `/v2/nft_collections`, account, `/v2/nft_sales` and network routes serve it.

**Tech Stack:** as in `2026-10-17-amm-data.md`.

**Spec:** `docs/superpowers/specs/2026-10-17-nft-data-design.md`. Shared rules are in `docs/superpowers/specs/2026-10-17-amendments-roadmap.md`. **Depends on:** the AMM plan, completed and merged into `feat/amm-data` (the `--txs` fixture mode, `PARSER_VERSION` 2).

## Global Constraints

Identical to the Global Constraints of `docs/superpowers/plans/2026-10-17-amm-data.md`; read them first. In addition:
- **Branch:** commit on `feat/nft-data`, cut from the finished `feat/amm-data`.
- **`PARSER_VERSION` = 3.**
- **NFT id validation:** an id must be 64 hex characters. Anything else gives 400 `invalid nft id`.
- **Aggregation cadence:**
  - `nft_daily` and `nft_collections` run every 5 ticks.
  - `nfts` and `account_nfts` run every tick under `AGGREGATOR_NFT_STATE_BUDGET_MS = 3000`.

## Review Focus

1. **A page split or merge in the same transaction as a mint or transfer.** The union-of-pages rule must report exactly one mint or transfer, never a burn plus a mint. Owner: Task 3, with a fixture or a synthetic split.
2. **A brokered sale.** Price, seller, buyer, broker and broker fee must match the offers, and the NFT must not be counted twice. Owner: Task 3.
3. **An account holding more than 100k NFTs.** Its `account_nfts` recompute and its `/v2/accounts/:a/nfts` pages must stay bounded. Owner: Task 6 (budget and read_rows tests with 120k synthetic NFTs).
4. **A URIToken moved by `Remit` (Xahau).** It is a `transfer`, and the owner is updated. Owner: Task 4.
5. **A sale priced in an IOU without a native rate.** It is counted in `sales_count` but not in `volume_native`, and `avg_price_native` / `min_price_native` ignore it. Owner: Task 7.

### Task 3: NFTokenID helpers and the XRPL NFT parser

**Files:**
- Create: `packages/shared/src/util/nftoken-id.ts` (+ spec)
- Create: `packages/shared/src/parsers/nft.parser.ts` (+ spec)

**Interfaces:**
- Produces:
  ```ts
  export interface NFTokenIdParts { flags: number; transferFee: number; issuer: string; taxon: number; sequence: number; }
  export function decodeNFTokenId(id: string): NFTokenIdParts;   // throws on non-64-hex
  export function pageOwner(pageLedgerIndex: string): string;   // classic address of the first 20 bytes
  export type NftEventType = 'mint'|'burn'|'modify'|'offer_create'|'offer_cancel'|'offer_removed'|'sale'|'transfer';
  export interface ParsedNftEvent { nft_id: string; kind: 'nftoken'|'uritoken'; event: NftEventType; event_index: number;
    issuer: string; taxon?: number; nft_flags: number; transfer_fee: number; uri?: string; from_account?: string;
    to_account?: string; offer_id?: string; is_sell_offer?: boolean; amount?: { currency: string; issuer?: string; value: string };
    destination?: string; expiration?: number; broker?: string; broker_fee?: string; royalty_est?: string;
    accounts: string[]; }
  export class NftParser { parse(t: ParserTx, ctx: ParseContext): { events: ParsedNftEvent[]; skipped: number }; }
  ```
  `accounts` lists every account the event is attributed to, for `account_nft_events`. `skipped` counts MPT-priced or unparseable cases.
