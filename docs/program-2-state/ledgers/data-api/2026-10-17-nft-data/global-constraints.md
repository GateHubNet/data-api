## Global Constraints

- **Install once:** if the worktree has no `node_modules`, run `pnpm install --frozen-lockfile`, then `pnpm build`. The apps import the compiled `dist/` of `packages/shared`: after changing it, run `pnpm --filter @gatehub/data-api-shared build` before an app's tests.
- **Commands:** `pnpm build` (the typecheck of every package), `pnpm test` (unit), `pnpm --filter @gatehub/data-api-shared test:e2e`, `pnpm --filter @gatehub/data-api-service test:e2e`, `pnpm --filter @gatehub/data-syncer test:e2e` (a real ClickHouse through testcontainers; Docker is available), narrowed with `-- <pattern>`. Before each commit, `pnpm format`, `pnpm build`, `pnpm test` and the `test:e2e` of every package the task touched exit 0. If the first e2e run cannot pull `testcontainers/ryuk`, run with `TESTCONTAINERS_RYUK_DISABLED=true` and say so.
- **Numbers (checked at build time):** the migration is `packages/shared/schema/011_nft_data.sql` (highest today `010_export_jobs.sql`; D-env adds none); `NFT_PARSER_VERSION = 5`, with `PARSER_VERSION` moving to 5 (today `PARSER_VERSION` 4, `STATE_PARSER_VERSION` 3, `PATH_PARSER_VERSION` 4, `AMM_PARSER_VERSION` 2); the ADR is `docs/adr/0016-nft-and-uritoken-data.md` (highest today 0015); the ADR-0010 amendment is "Amendment 5" (PR #20's is Amendment 4; D4 takes 6). The task that takes a number first checks that it is still the next free one. If PR #20 or D-env took it, use the next free value and change every reference in that task and in this plan's later tasks.
- **Repo conventions** (`docs/development.md` §5): table names only from the `Table` enum; every user-derived value bound as a query parameter; no `FINAL` (ADR-0003); key-ordered reads; exact decimals as strings with `BigNumber` (the `*_f` Float64 shadows only for sorting and SQL sums); config only through the config classes; everything new of `packages/shared` exported from `packages/shared/src/index.ts`.
- **Schema rules:** every statement is `CREATE TABLE IF NOT EXISTS` and ends with its semicolon on its last line; no other line, comments included, ends with one. Never edit a migration that has been applied. The five ledger tables are `ReplacingMergeTree` with `SETTINGS non_replicated_deduplication_window = 1000` and appear in `CHILD_TABLES` and `LEDGER_KEYED_TABLES`; the aggregates are `ReplacingMergeTree(version)` and appear in neither.
- **Values:** ids are 64 upper-case hex digits; `kind` is `nftoken` (XRPL) or `uritoken` (Xahau); `taxon_key` is the taxon on XRPL and 0 on Xahau; `serial` is the id's sequence on XRPL and 0 on Xahau; an absent string is `''` and an absent number `NULL`; amounts are exact decimal text in whole units, the native currency is `XRP` or `XAH` with `amount_issuer` `''`; `transfer_fee` is in 1/100000.
- **API answers:** the contract layer (`@RippleController`, `@RippleRoute('<message>')`, `limit` 200 max 1000, base64url keyset markers and `Link`, `@Csv`, absent keys left out, key order = the exported `*_KEYS` constants, pinned by tests). Times are `YYYY-MM-DDTHH:mm:ssZ` (`fmtTime`) and days `YYYY-MM-DDT00:00:00Z`; `converted_amount` and `*_native` are native-currency text with at most 6 decimals, no trailing zeros and no exponent. Every new route sends `Cache-Control: private, max-age=60` (only when `GH_CACHE_CONTROL` is set; errors send `no-store`, as today).
- **Coverage** (spec §4): `"coverage": { "from_ledger_index": N, "complete": bool }`, keys in that order, is the key right after `result` on every new answer of this plan and is not in the CSV. `from_ledger_index` is left out when no ledger is stored. Enable ledgers come only from the amendments data (`AmendmentsService`), never from a constant.
- **Reads** are capped at the newest committed ledger (`ledgers`). Event lists use `readDistinctPage`; lists of the version-set tables use `readNewestPage` (Task 13). Each bound of spec §6 has its test in the task that owns the read.
- **Aggregator:** committed ledgers only; version sets (a version is the ClickHouse clock in milliseconds, above the key's newest); R86 finality; budgets; failed-last ordering; one runner per job, in a file of its own, behind `AggregatorJobContext`; errors counted and logged, never stopping the loop; nothing written once shutdown has begun.
- **Recorded data:** fixtures and node answers come from public nodes (`wss://s2.ripple.com`, `wss://xahau.network`, `https://s1.ripple.com:51234/`). If outbound network fails, stop and report BLOCKED. Never hand-write data and present it as recorded: a hand-made transaction says so in its name (`synthetic-…`) and in its test.
- **Delete nothing** you did not create: no `rm` of existing files, no `git clean`, no database or container you did not start. Never touch `.claude/`.
- **Commits:** Conventional Commits as the repo writes them (`feat(shared): …`, `feat(syncer): …`, `feat(api): …`, `test: …`, `docs: …`), with a body saying why, ending with the line `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Name the files in `git add` (never `-A`); never `--amend`.
