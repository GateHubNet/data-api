## Settled decisions (owner, 2026-10-24)

Environments and networks
- Production runs on XRPL and Xahau mainnet; the **sandbox** (renamed from "staging" everywhere) on XRPL Testnet and Xahau Testnet.
  Hosts: explorer `explorer.gatehub.net` / `explorer.sandbox.gatehub.net`; data API `xrpl.data.gatehub.net`,
  `xahau.data.gatehub.net` / `xrpl.data.sandbox.gatehub.net`, `xahau.data.sandbox.gatehub.net`. Same `/xrpl`, `/xahau` paths in
  both; the sandbox labels them "XRPL Testnet" / "Xahau Testnet" and shows a "Testnet" badge in the header.

Account names (display names)
- **Display name** = the account's verified name, else its account name, else its unverified domain; names replace shortened
  addresses everywhere, with the full address on hover.
- **Verified name**: two-way check — the account's Domain field names a domain, and that domain's toml (`xrp-ledger.toml` /
  `xahau.toml` at `/.well-known/`) lists the address under `[[ACCOUNTS]]`; the name is that entry's `desc`, else the domain.
- **Account name** (+ **account network name**): written by GateHub (PR #20's shared `account_names`, per-network
  `account_network_names`), shown as "Named by GateHub". **Unverified domain**: shown with a "not verified" mark.
- **Labels** (PR #20: scam, spam, advisory): a warning banner on a labelled account's page and a small warning mark next to its
  name wherever it appears. Nothing more.
- Use all toml sections: `[[VALIDATORS]]` (owner/server country, network, UNL), `[[ACCOUNTS]]` (names), `[[CURRENCIES]]` (token
  details), `[[PRINCIPALS]]` (names only, never emails), `[METADATA]` (last modified). `[[SERVERS]]` is not used (nodes deferred).
- **The names contract** (drafter B owns its detail; everyone else uses it as-is): one batch endpoint
  `GET /v2/account_names?addresses=<a1>,<a2>,…` (1–100 classic addresses), answering in request order
  `{ "result":"success", "count":N, "account_names":[ { "address", "display_name"?: { "text", "kind": "verified"|"account"|"domain" },
  "domain"?, "account_name"?, "account_network_name"?, "labels"?: { "<label>": { "description", "source"?, "url"? } } } ] }`
  (absent fields omitted, as everywhere in this API). It amends ADR-0014 (which rejected lookup endpoints). Each explorer loader
  collects its page's addresses and makes one cached call; components never fetch. `AccountLink` renders a display name.

Ledger history and current state
- State is derived from transaction metadata (ADR-0015's approach). A **detail page** (NFT, escrow, check, payment channel, MPT
  issuance) reads current state from the node (`ledger_entry` etc.) when the index doesn't have the object. **Lists and counts
  say which ledger their coverage starts at.** Common shape on new list/aggregate answers:
  `"coverage": { "from_ledger_index": <n>, "complete": <bool> }` (complete = the index holds this feature's history from the
  ledger its amendment was enabled). The explorer shows a short notice under a list whose coverage isn't complete.

Feature switches (explorer), one per feature: `NFTS`, `NAMES`, `LEDGER_OBJECTS`, `DELEGATION`, `TOKENS`, `SUPPLY`,
`VALIDATORS_MAP`, `MPT`. On at top level and in tests; off in sandbox and production until that environment's data API has the
feature. An off page answers 404 and its nav link reads "soon", as today.

Scope cuts (owner agreed these are deferred; don't design them): the nodes crawler, Nodes/Node pages and the nodes map;
Distribution (rich list, brackets, percentiles); **history charts that need a new daily statistics job** (token holders or
supply over time, MPT holders over time, escrow release forecasts); the network-wide escrows list. A chart whose data already
exists (e.g. fees burned per day from `/v2/network/fees`) or is a cheap query over tables you're designing anyway may stay; say
which in your decisions table. Token price and 24 h volume come from the existing markets data, which is still filling.

Build order (sub-project IDs): D3 NFTs, E7 sandbox, E8 NFT pages, D4 names, E9 names, D5 ledger objects + delegation, E10 object
pages + delegation, D6 issued tokens, E11 token pages, D7 supply, E12 supply page, D8 validator toml details, E13 validators map +
validator toml card, D9 MPT, E14 MPT page + the token list's MPT tab. Specs of later features may rely on earlier ones (say what).
The environment pair (D-env testnet profiles + E7) is built before E8.
